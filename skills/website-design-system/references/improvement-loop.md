# Improve the system from actual work

The owner-authorized niche network expects builders to improve maintained rules, skills, prompts and helpers when practical work demonstrates a reusable defect. Read the active companion's `CORE_IMPROVEMENT.md` when present and follow its coordination and validation contract. Outside that network, use the actual task's maintenance authorization; this portable skill does not grant new service, messaging or deployment rights.

1. Record the observed problem and evidence in the project's existing feedback log, conventionally `sites/<siteId>/CORE_FEEDBACK.md`. State the effect and whether the cause is a general instruction/helper or a site-specific design/fact. A possible future idea is not an experienced defect.
2. Read the maintained implementation/instructions and identify one source of truth. Preserve imported source archives, historical fingerprints and original failed evidence. A niche's palette, product price or business fact must not become a network default.
3. Check current Git/PR/file ownership before shared writes and reserve a narrow window under the project's rules. Do not overwrite another workstream; keep a specific dependency and continue independent work when overlap cannot be resolved within authorized coordination.
4. Fix a small demonstrated cause, plus necessary references/distribution metadata, within authorized scope. Large architecture/schema/migration changes need their own scoped work; do not create a per-site duplicate of shared infrastructure. Routine authorized maintenance does not require a new owner approval or mandatory execution by a root agent.
5. Verify proportional to risk: instruction conflicts, discoverability, references and realistic scenarios for a skill; reproduction/regression and applicable existing checks for code. Preserve acceptance thresholds. If a check itself is wrong, save the original result and verify a versioned correction against actual evidence.
6. Record changed paths, source revision, checks and precise status: observed, fixed locally, verified, PR, merged or adopted. Distribute through the existing Git/scoped PR process and synchronize installed skill copies where applicable. A pushed unmerged PR is available for review, not proof every other agent has adopted it.

Revisit the log before finishing. If no meaningful shared improvement is demonstrated, record that outcome without inventing a change. New rule text does not retroactively certify old sites. This workflow is builder-led maintenance, not automatic promotion of an executing business agent's learned policy.

A demonstrated multipage completion defect was treating designed commerce/contact/account pages as the whole site while useful guides, editorial trust and the active SEO/publication audit remained unhandled. Repair the workflow with an evidence-backed completion matrix and the maintained site's actual acceptance catalog. Repair code through shared formatters/projection, with incumbent output regressions and local-versus-public status recorded. Do not respond by making every niche publish arbitrary articles, adding unsupported ranking guarantees, or certifying absent mail/domain/measurement integration.

Two reusable checks demonstrated by multipage implementation: keep agent decisions, owner delegation and generation provenance in private planning records rather than customer-facing copy; make page generators idempotent and explicitly read/write UTF-8 so regeneration preserves approved text and does not duplicate shared navigation. For frozen surfaces, compare the unchanged regions/files against the saved baseline after regeneration. Preserve the failed result when fixing the generator or check.
