# Asset-kit contract

Use project conventions. An illustrative layout is private `design/source/<version>/` masters/prompts, `design/concepts/<version>/` selection notes, permitted `assets/<version>/` web files, and `verification/<version>/` real QA. When a CMS owns media use its existing stores/importer. Private originals/prompts/local paths must not leak into public exports.

## Inventory

Each visual role needs id/purpose, raster-cutout/integrated-photo/SVG/CSS/live-content representation, reuse/edit/generate decision, source/input role, invariants, actual CSS width/aspect ratio, focal region/mobile behavior, alpha or opaque backdrop policy, meaningful alt/decorative intent, and status.

One product master can appear in multiple quantity arrangements; numbers/labels stay live. Different finishes need reviewed sources. Card surfaces share a reusable CSS recipe with selected-state modifiers. Neither card count nor raster count is a fixed quota.

## Manifest and provenance

Use the existing schema when present; otherwise record privately:

- Site/section, version, selected concept path/hash, selection actor/date.
- Masters: actual MIME, decoded dimensions, bytes, SHA-256, alpha characteristics.
- Reuse origin or exact prompt record, tool mode, inputs/hashes/roles, truthful rights/licensing statement, limitations. Holding a reference file does not establish rights.
- Derivatives: path, actual dimensions/bytes/hash, format/pipeline policy. A resize is not a newly generated composition.
- SVG/CSS files, viewBoxes/stroke conventions, surface/state recipes, copy source/language.
- Crop/focal region, actual srcsets/sizes, loading intent, semantic alt/decorative treatment.
- Actual evidence/results, unresolved issues, asset/implementation/publication states separately.

Unmeasured fields stay unknown. Requested resolution is not actual resolution; hashes are integrity evidence, not visual proof. Do not expose private absolute input paths as browser URLs.

## Derivatives

Use canonical pipeline limits/quality/format policy. Preserve required alpha, actual MIME and immutable originals. Avoid enlargement/duplicate widths; useful widths follow CSS size and density within project limits. Visually inspect the web derivative: resolve damaged fine UI/edges through supported policy, not a new per-section optimizer. Strip sensitive metadata through the pipeline while preserving required credits.

`sizes` describes rendered width. Different compositions/crops need appropriate semantics/responsive handling; resize variants share alt. Significant copy belongs in HTML or an accessible equivalent.

## Quality checks

### Product fidelity

Compare silhouette, proportion, count, scale, perspective, alignment, hardware geometry, materials and variants to sources. Compare brand marks to vectors; equal shapes remain equal, laser engraving/embossing/print differ. Check prominent printed words; small generated UI needs an approximation note or actual screenshot workflow. A prompt is not precision evidence. Exclude invented parts, annotations, extra objects and stock watermarks; do not remove a watermark to republish an unlicensed source.

### Alpha and edges

Decode actual alpha: opaque, binary transparency and soft partial alpha differ. Sample exterior regions and interior holes; inspect corners only where expected empty. Transparent corners alone do not prove quality; no universal transparent-pixel percentage applies. Review dark/light/checker at actual scale and close-up for fringes, opaque patches, hard crops, broken glow and baked checkerboard. Separate intentional shadow from contamination. Verify derivative alpha survives. Opaque photographs instead need backdrop, edge, crop and illumination checks.

### Rendered section proof

Use final images, live copy, vector icons and actual surface CSS. Compare scale, lighting, negative space, reflections and selected states to the chosen concept. Do not substitute flat fills where lighting/texture defines the design. Check desktop/narrow/mobile reflow at intended width, image decoding/natural dimensions, files/srcsets, SVG rendering and horizontal overflow; record runtime errors.

For implementation tasks additionally verify real links/controls, keyboard focus, semantic selection, contrast, reduced motion and project acceptance checks. A gallery of decorative states does not prove a working shop. Technical PASS and subjective visual review remain separate.

## Delivery gate

Asset-ready: required layers and surface recipes present, files/provenance agree, intended composition inspected. Section-implemented: responsive semantic code and requested behavior. Locally-verified: actual applicable browser/tests. Published: separate authorized delivery/publication gates passed. A generation result is not acceptance. Preserve selected/superseded variants and report actual checks and remaining limits.
