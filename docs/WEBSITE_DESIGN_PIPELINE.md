# Website design pipeline

Owner-authorized shared-rule extension, 2026-10-06, following the PhoneBridger homepage workflow. Apply [website-design-system](../skills/website-design-system/SKILL.md) for an open identity, substantial redesign or extending an established brand across requested page families. Apply [webpage-section-asset-kit](../skills/webpage-section-asset-kit/SKILL.md) within that process for image-led concepts and production assets.

## Working sequence

1. Establish the active niche, audience, actual offer, existing decisions, authorized stage and requested pages. Reuse current research; new identities need substantive niche/craft evidence and project-required cross-site comparison.
2. Plan the complete authorized route/journey and homepage sequence before final asset production. Record page purpose, real next action, content/data sources, public/private/prototype status, state/dependency and observable acceptance.
3. Choose or preserve a niche-specific visual thesis. Plan whole-page desktop/mobile structure, shared token/component roles, imagery/icon language and section junctions. Refine detailed CSS with actual composition instead of freezing every implementation choice prematurely.
4. Calibrate a representative composition in the real browser before scaling. A chosen identity extends across pages; functional page families adapt density and decoration to their jobs.
5. Repeat page/section brief → useful concept → asset/reuse decisions → focused separate assets → responsive semantic code → actual composition/interaction review. Exact SVG/UI and live copy remain exact; complex raster imagery uses ImageGen when appropriate. No generation quota or mandatory image for every region.
6. Reuse approved masters and shared surfaces, preserving scale/light/product fidelity. Match section transitions and review neighbouring regions plus the full reading sequence. A separator is a design decision, not a compulsory ornament.
7. Review the full page set on desktop/mobile, relevant states, keyboard/reflow, actual journeys, media and applicable measured performance. Repair observed issues, preserve evidence and distinguish local visual/frontend/backend/publication states.
8. Feed demonstrated reusable defects back into maintained rules, skills or helpers under the [improvement loop](../skills/website-design-system/references/improvement-loop.md). Authorized builders fix small coordinated issues themselves, verify them and record actual Git/adoption status. No artificial change quota, threshold weakening or retrospective rewrite of evidence.

## Flexible page families

Completion covers the authorized journey and the active site's content/search/publication contract, not just the visual page list. Keep an evidence matrix for supporting guides, editorial trust, shared metadata/schema/link/media projections, crawl behavior, optional LLM exports, backend outcomes and deployment. Apply the maintained site's actual audit, including unresolved frozen-surface and production dependencies; do not invent a universal article quota or imply a prepared preview is live. See [acceptance](../skills/website-design-system/references/acceptance.md).

The skill includes conditional guidance for homepage/marketing, shop/product choice, contacts, login/register/recovery, operational/creator dashboards and editorial/help/legal pages. No universal layout or module list is imposed. Shops prioritize meaningful product choice and the actual transaction/enquiry path; forms prioritize completion and recovery; dashboards prioritize roles, tasks and readable information. Pages share identity without copying one promotional hero or glowing card onto every route.

New niche phase-one defaults coexist with explicitly scoped later or private product work; this document changes neither stage rules nor runtime contracts.

This is an additive visual-planning/delivery workflow. It changes no schema, optimizer, renderer, authentication/payment service, native app, business facts or live deployment. It adds no mandatory user approval for already delegated reversible design work. Absent capabilities remain explicit dependencies; private synthetic states are not production proof.

## Authorized production release

Use [website-deploy](../skills/website-deploy/SKILL.md) when the owner requests a
launch, production update, hosting migration or deployment runbook. It preserves
shared publication, DNS/mail/data and frozen regions, checks the hosted edition
and records rollback and remaining gates. Preparing instructions or a local
build does not activate live services. Provider guidance is conditional; a static
site does not inherit this product's accounts, D1, mailbox or download workaround.
