# Exact V2 renderer build identity

The maintained compiler adds an optional `buildSourceRevision` to its existing generated V2 admission entry. `packageSha256` is the digest validated against the original imported UTF-8 package bytes; it is not a digest of the serialized registry, projected page, visible inventory or HTML. The runtime accessor returns identity only when both digests are valid. No request header, environment variable, CLI source assertion, acceptance status or production permission supplies either digest.

Source identity requires the actual compiler root to be the canonical public Git repository root, a valid HEAD containing the available origin/main ancestor, and no changed or untracked execution source. Content-package/staging/media inputs and the two maintained generated registry files are explicitly separate data inputs. Both source observations surrounding compilation must agree, and original admission/package binding is rechecked before proof is emitted. The compiler does not fetch; the owner must run the companion freshness gate before a meaningful build batch. Missing Git, exported copies beneath an ancestor repository, dirty source or an unavailable baseline withhold proof while ordinary rendering continues.

For an already admitted matching V2 package, proxy responses carry `x-niche-package-sha256` and `x-niche-source-revision` on page/SEO/media and scoped rejection paths. They identify the build that processed that request, including expected404s; they do not assert a requested resource exists. Unknown hosts, forbidden actual-host local previews and unrelated legacy routes do not receive target-package proof. Existing publication, media, internal-route, host and local/production admission rules remain authoritative. The source/package headers grant no additional access, editorial acceptance, deployment or agent readiness.

An actual-host `local-preview` still requires testOnly admission in an isolated output checkout and accepts only localhost/127.0.0.1. A `.example` local-fixture remains a separate synthetic permit. Canonical metadata/SEO URLs remain the package's canonical host. The caller's maintained local verifier must select its loopback transport explicitly rather than sending the real canonical Host to a local-preview. It must also select the exact native site through the existing server-owned `NICHE_DEV_SITE_ID` and check both digests against its frozen release/source scope.

A trusted preview producer therefore needs a real isolated public Git checkout at its frozen source (not a source copy accidentally inheriting parent Git), the exact immutable release imported through the existing bounded admission path, and an owned local build/server with external channels held. A separate archive provenance protocol is not implemented here. Package/source identity does not establish pixels, facts, language, inquiry storage or A–Z quality; actual separately reviewed evidence remains required.

For provider-zero protocol reproduction, commit the source, run `node tests/bound-build-http.mjs prepare outputs/<new-name>/dovanos-memorycasting`, and build/start that detached owned checkout with `NICHE_DEV_SITE_ID=headerpreview`. `check` takes that same relative directory and explicit local HTTP URL. `prepare-untrusted` creates a source copy without its own Git root; the same normal renderer must work while both identity headers remain absent. Each HTTP run retains a separate PASS/FAIL digest receipt. These fixtures use labelled synthetic approvals and testOnly permits, not manual editorial/A–Z PASS records. The installed dependency link is bound to the supplying checkout's exact package-lock; no environments, secrets or original runtime data are copied.
