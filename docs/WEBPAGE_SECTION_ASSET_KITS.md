# Webpage section asset kits

For a whole-page or multipage design task first apply the
[website design pipeline](WEBSITE_DESIGN_PIPELINE.md). This asset-kit cycle
implements its image-led regions and shares the active design/asset records;
it does not restart brand research or mandate generation for every section.

Owner-authorized shared workflow rule, 2026-10-05. Apply
[webpage-section-asset-kit](../skills/webpage-section-asset-kit/SKILL.md) when
creating image-led section concepts or turning a chosen mockup into production
materials. This includes substantial image-led redesigns where the workflow
benefits the brief; it does not add generation to small copy/CSS or vector fixes.

## Required workflow

1. Establish the active site's business facts, language, section purpose,
   existing art direction, approved sources and implementation scope.
2. Generate ImageGen concepts when appropriate. Record the selected direction
   and selection actor; exercise delegated creative authority without inventing
   extra approval gates.
3. Inventory every visible role. Reuse originals, produce faithful cutouts or
   integrated photographs, preserve native SVG logos/icons, and keep copy,
   quantities, cards and controls in live HTML/CSS.
4. Retain exact prompt/input provenance privately. Use the existing MEDIA_CORE
   importer and responsive pipeline; preserve actual dimensions/alpha and
   immutable asset families. Do not introduce a parallel optimizer.
5. Prepare all required surface recipes, including light, texture, border,
   shadow and selected-state treatment. An isolated PNG collection is not a
   finished reproduction of a selected section design.
6. Inspect reference fidelity and relevant dark/light/checker edges, then
   review the actual desktop/narrow/mobile composition. For requested
   implementation continue through real behavior and project acceptance.
7. Report asset-ready, implemented, locally verified and published separately.

## Compatibility and distribution

The private companion's README, AGENTS, START_HERE, WORKSTREAMS,
docs/MULTI_MACHINE, docs/INTEGRATING_A_PROJECT, SKILLS/PROJECT_CONTRACT,
MEDIA_CORE and applicable builder/planner/audit/impeccable instructions remain
authoritative. This is a visual-production helper, not a replacement site
builder, commercial phase decision, publication gate or shared runtime.

Source distribution is `skills/webpage-section-asset-kit/`. Copy that folder
to the configured `$CODEX_HOME/skills/` (default `~/.codex/skills/`) to install
personally. Invoke `$webpage-section-asset-kit`, or read its SKILL directly in
a repository session. A Git source copy is not automatic installation on every
machine. Companion catalog integration, if later required, follows its own
scoped process; no catalog or runtime loader is changed by this rule.

The core's root AGENTS and GITHUB_WORKSPACE link to this rule. Art direction,
business facts, contacts, prices, products and language remain site-specific.
Private product originals are not bundled into this generic helper. Generated
mockups are not evidence of inventory, customer work or current functionality.

## Scope and evidence

This change is limited to the skill source, this rule and discovery links.
It changes no media processing, package schema, runtime, native application,
other-site content, publication or deployment. Its GitHub PR is the registered
shared-file scope under MULTI_MACHINE. Skill structure, relative links and
personal/core-copy integrity are checked before delivery; these checks are
not application/browser QA or proof of a finished website.

core copies; all five skill files were byte-identical, nine Markdown links and
